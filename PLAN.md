# MCP-сервер метаданных 1С 7.7 — план и статус

Обновлено: 2026-11-11

## Статус

**Все этапы E0–E7 закрыты, плюс три пост-релизных пункта:** второй источник (текстовая
выгрузка), разметка форм и SQLite-индекс.

- Разбор `1Cv7.MD` (OLE + дерево секций): 671 объект, 16 МБ, ~0,2 с.
- Модель: справочники (91), документы (53), регистры (17), перечисления (51), константы (168),
  журналы (34), отчёты (104), обработки (149), календари, нумераторы; реквизиты, ТЧ, типы, ссылки.
- Модули: 457 непустых (201 667 строк) — глобальный, проведения, формы, отчёты, обработки.
- Формы: состав, модуль и элементы из `Dialog Stream`; Moxcel-страницы `Page.1`/`Page.2` не разбираются.
- Экспорт: JSON (1,0 МБ), Markdown (49 КБ), Mermaid (15 КБ), SQL DDL (104 КБ).
- Аудит: 6 проверок (битые ссылки, неиспользуемые, дубли синонимов, объекты без форм,
  документы без проведения, пустые объекты).
- MCP-сервер на stdio, 10 инструментов; подключён в DSH как `mcp__onec77md__*`.
- Упаковка: `pyproject.toml`, wheel `dist/onec77_md_mcp-0.3.0-py3-none-any.whl`,
  консольная команда `onec77-md` с подкомандами `serve/info/objects/object/module/export/audit/index`.
- Второй источник: текстовая выгрузка (каталог или одиночный `*.md`), автоопределение по пути.
- Разметка форм: `Container.Contents` — манифест, `Dialog Stream` — дерево элементов;
  читаются класс, подпись, координаты, обработчик и привязанный реквизит.
- SQLite-индекс: 201 367 строк модулей, построение 0,6 с, поиск 0,09 с, откат на перебор.
- Разбор языка 7.7: 7 914 символов (процедуры, функции, переменные) и вызовы с контекстом;
  комментарии и строковые литералы отбрасываются до анализа.
- Граф вызовов `md_call_graph`: вверх/вниз, глубина 1–5, только символы конфигурации,
  схлопывание повторных вызовов со счётчиком, защита от циклов и лавины узлов.
- 55 тестов — зелёные.

Дальше по желанию: Moxcel-страницы форм (`Page.1`/`Page.2`), иерархия групп на форме,
инкрементальное обновление индекса.

## Решения

| Решение | Значение |
|---|---|
| Источники | `1Cv7.MD` (OLE) и текстовая выгрузка, автоопределение по пути |
| Объём | чтение/навигация, поиск, модули и формы, аудит, экспорт |
| Запись | строго read-only |
| Стек | Python 3.12, `mcp` 2.3 (MCPServer), `olefile`, зависимости локально в `.deps` |
| Транспорт | stdio |
| Клиенты | Claude Desktop / Cursor / Cline + DSH |

## Формат (проверено на живой базе)

- `1Cv7.MD` — OLE2-контейнер, основной стрим `Metadata/Main MetaData Stream`: CP1251,
  дерево `{идентификатор, параметр, {вложенная секция, ...}}`, до/после дерева — мусор.
- Верхние секции этой платформы: `MainDataContDef`, `TaskItem`, `GenJrnlFldDef`, `DocSelRefObj`,
  `DocNumDef`, `Consts`, `SbCnts`, `Registers`, `Documents`, `Journalisters`, `EnumList`,
  `ReportList`, `CJ`, `Calendars`, `Algorithms`, `RecalcRules`, `CalcVars`, `Groups`,
  `Document Streams`, `Buh`, `CRC`.
- Объект: `[id, Имя, комментарий, синоним, ...]`; реквизиты — `[id, Имя, синоним, комментарий,
  тип, длина, точность, ссылка]`; у документа `Head Fields` + `Table Fields`, у регистра
  `Props`/`Figures`/`Flds`, у перечисления `EnumVal`.
- Типы: `U` неопределённый, `N` число, `S` строка, `D` дата, `B` справочник, `O` документ,
  `E` перечисление, `T` счёт, `P` план счетов, `K` субконто, `C` календарь, `A` вид расчёта.
- Модули: 941 стрим `MD Programm text` (zlib, срезан заголовок `78 9C`) в `TypedText`
  (глобальный модуль, модули проведения), `Document`, `Report`, `SubList`, `SubFolder`, `Subconto`.
  Формы — `Container.Contents`/`Container.Profile` в `Document`, `SubList`, `Report` и т.д.

## Архитектура

```
1Cv7.MD -> OleMdSource -> RawConfig -> build_config -> Config -> formatting -> MCP tools
```

Слои разделены: ридер (OLE/текстовая выгрузка/XML), разбор секций, модель, представление,
транспорт. Новый источник добавляется без правок модели.

| Риск | Мера |
|---|---|
| Разные версии 7.7 (36/64-ричные id, иные секции) | неизвестные секции игнорируются, модель не падает; проверять на других базах |
| Модули/формы в OLE-стримах | реализовано: raw deflate для модулей, `Dialog Stream` для форм |
| Большие конфигурации | индекс SQLite + лимиты ответов (сейчас линейный поиск, для 671 объекта хватает) |
