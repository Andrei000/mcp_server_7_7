# onec77-md-mcp

MCP-сервер метаданных конфигурации **1С:Предприятие 7.7**. Читает `1Cv7.MD` напрямую
(OLE-контейнер, без Конфигуратора и COM) и отдаёт агенту структуру конфигурации:
справочники, документы, регистры, перечисления, константы, журналы, отчёты, обработки —
с реквизитами, табличными частями, типами и ссылками.

Только чтение: файлы базы не изменяются.

## Быстрый старт

```bash
pip install .
export ONE77_MD_PATH=/path/to/base          # Windows: set ONE77_MD_PATH=D:\base
onec77-md info                               # сводка по конфигурации
onec77-md objects --kind document            # список документов
onec77-md serve                              # MCP-сервер по stdio
```

Подключение к Claude Desktop / Cursor:

```json
{
  "mcpServers": {
    "onec77md": {
      "command": "onec77-md",
      "args": ["serve"],
      "env": { "ONE77_MD_PATH": "/path/to/base/1Cv7.MD" }
    }
  }
}
```

Путь может быть файлом `1Cv7.MD`, каталогом базы или каталогом текстовой выгрузки —
тип источника определяется автоматически.

## Что умеет

| Инструмент | Назначение |
|---|---|
| `md_config_info` | имя конфигурации, источник, количество объектов и модулей |
| `md_list_objects` | список объектов с фильтром по виду и подстроке имени |
| `md_get_object` | карточка: реквизиты шапки, ТЧ, значения перечисления, формы, модули |
| `md_find` | поиск по имени/синониму/комментарию объектов и по реквизитам |
| `md_get_attribute` | один реквизит: тип, длина, точность, ссылка |
| `md_get_module` | текст модуля с нумерацией строк (глобальный, объекта, формы, проведения) |
| `md_search_modules` | поиск по текстам всех модулей с объектом и номером строки |
| `md_find_symbol` | где объявлена процедура/функция/переменная (точное имя) |
| `md_find_calls` | настоящие вызовы символа, без комментариев и строковых литералов, плюс обработчики форм |
| `md_call_graph` | граф вызовов вверх/вниз до 5 уровней, только символы конфигурации |
| `md_propose_rename` | предложить переименование: unified diff, только код, база не меняется |
| `md_propose_replace` | предложить точечную замену текста в коде |
| `md_get_form` | формы объекта: имена, id, модуль и элементы формы (кнопки, поля, таблицы) |
| `md_export` | экспорт в файл: `json`, `md` (справочник), `mermaid` (схема связей), `sql` (DDL) |
| `md_audit` | проверки: битые ссылки, неиспользуемые, дубли синонимов, пустые объекты |

Виды объектов понимаются и по-английски, и по-русски: `catalog`/`справочник`,
`document`/`документ`, `register`/`регистр`, `enum`/`перечисление`, `const`/`константа`,
`journal`/`журнал`, `report`/`отчёт`, `processing`/`обработка`, `calendar`/`календарь`.

## Источники

Источник определяется по пути автоматически:

| Что подано | Как читается |
|---|---|
| файл `1Cv7.MD` или каталог базы, где он лежит | OLE2-контейнер |
| каталог с `*.md`-файлами (выгрузка «Конфигурация → Выгрузить в файлы») | текстовое дерево, файлы склеиваются |
| одиночный текстовый `*.md` | текстовое дерево |

В текстовой выгрузке модулей нет — там только описание метаданных; `md_config_info` честно
показывает тип источника. Кодировка файлов определяется сама (UTF-8, затем CP1251/CP866).

## Модули и формы

Модули лежат в OLE-стримах `MD Programm text` (raw deflate; в части версий — zlib с заголовком,
поэтому пробуются оба варианта). На тестовой конфигурации это 941 стрим, из них непустых — 457 модулей
на 201 667 строк:

| Что | Стрим | Сколько |
|---|---|---|
| Глобальный модуль | `TypedText/ModuleText_Number1` | 1 (17 240 строк) |
| Модуль проведения | `TypedText/Transact_Number<id документа>` | 50 |
| Модуль формы документа | `Document/Document_Number<id>` | 53 |
| Модуль отчёта | `Report/Report_Number<id>` | 104 |
| Модуль обработки | `CalcVar/CalcVar_Number<id>` | 149 |
| Модуль формы списка | `SubList/SubList_Number<id формы>` | 48 |
| Модуль формы элемента | `SubFolder/SubFolder_Number<id справочника>` | 6 |
| Модуль формы субконто | `Subconto/Subconto_Number<id справочника>` | 46 |

`UserHelp_*` (360 стримов) — тексты справки, к модулям не относятся и пропускаются.

### Разметка формы

Формы 7.7 оказались не бинарным монолитом: `Container.Contents` — текстовый манифест потоков
формы, а `Dialog Stream` — такое же дерево `{...}`, как MD. Поэтому из формы читаются элементы:

```
Справочник.Контрагенты — формы (2):
  - ФормаСписка, id 1158, модуль: 486 строк
    элементов: 14
      · STATIC «Телефон:» 18,190 33×9
      · BUTTON «Выход» 397,203 44×15 обработчик: #Закрыть
      · BUTTON «Счета» 18,203 44×15 обработчик: ОткрытьФорму("Справочник.РасчетныеСчета.ФормаСписка",)
      · CHECKBOX «- активность клиента» 194,222 93×10 обработчик: ПриИзмененииАктивности()
```

У элемента берутся класс (`BUTTON`, `STATIC`, `1CEDIT`, `COMBOBOX`, `TABLE`, `1CGROUPBOX`,
`CHECKBOX`), подпись, координаты и размеры, обработчик или привязанный реквизит, тип.
Не разбираются страницы `Page.1`/`Page.2` — это Moxcel-таблицы на форме, отдельный формат.

### Обработчики кнопок

Строки обработчиков индексируются вместе с модулями — 2 570 ссылок на 1 524 формы, — поэтому
поиск и граф видят то, чего нет в коде:

```
Вызовов «ПоискКонтрагента» не найдено (комментарии и строковые литералы не учитываются).

Обработчики форм «ПоискКонтрагента»: 1
  форма 1158 [Справочник.Контрагенты], BUTTON: ПоискКонтрагента()
```

Построение индекса подорожало с 2,4 до 3,1 с — это плата за обход всех форм.
`md_propose_rename` добавляет такой список в предупреждение и складывает полный перечень
в `handlers.txt` рядом с патчем: строки лежат в `Dialog Stream`, diff их не содержит,
правит человек в Конфигураторе.

## Символы и вызовы

Поверх текстов модулей работает разбор языка 7.7: комментарии и строковые литералы
заменяются пробелами, после чего ищутся объявления и вызовы. Поэтому `// ПоискКонтрагента`
и `"ПоискКонтрагента"` в выдачу не попадают — в отличие от обычного поиска по подстроке.

```
onec77-md symbols ОбработкаПроведения
onec77-md calls ПолучитьЗначение
```

```
Объявлений «ОбработкаПроведения»: 3
  Процедура ОбработкаПроведения(Парампроведения)
      АгентскийБонус [Модуль проведения] :2–32
  Процедура ОбработкаПроведения()
      АктНесоответствия [Модуль проведения] :3–28

Вызовов «ПолучитьЗначение»: 4
  OLAP [Модуль обработки] :195 — Создать_Структуру_ДБФ
  V7Exp77 [Модуль отчёта] :4252 — ПолучитьРеквизитПКО
```

Разбираются: `Процедура`/`Функция` с параметрами и признаком `Экспорт`, `Перем` (модульные
и локальные), вызовы `Имя(` с указанием вызывающей процедуры и строки. Заголовок может
занимать несколько строк, а предварительное описание `Функция Имя(...) Далее` учитывается
отдельно: это не тело, и вызовом оно не считается. На тестовой конфигурации 7 914 символов,
построение индекса вместе с разбором — 2,4 с.

Что это даёт для рефакторинга: точный ответ «где определено» и «кто вызывает» вместо
«вот 300 строк, где встречается подстрока».

### Разрешение вызовов

Вызов привязывается к конкретному объявлению по правилам (по убыванию приоритета):

| Правило | Когда | Пример |
|---|---|---|
| `local` | процедура объявлена в том же модуле | `ОбработкаПроведения` вызывает свой же `ПроверитьЗаполнение` |
| `global` | объявлена в глобальном модуле **с `Экспорт`** | `глЕстьЛицензияБлокировок` |
| `unique` | во всей конфигурации ровно одно **экспортное** объявление | редкая функция отчёта |
| `ambiguous` | экспортных объявлений несколько и они в чужих модулях | `ПолучитьЗначение` из обработки — не угадываем |

Правило `local` закрывает основную массу: одноимённые `ОбработкаПроведения` в 53 документах
живут в разных модулях и друг друга не видят. Неоднозначные вызовы `md_find_calls` помечает
явно, а граф показывает одноимённые объявления отдельными корнями:

```
Граф «ПолучитьЗначение»: кто вызывает, глубина 1, объявлений с этим именем: 3
— объявление 1 из 3 —
ПолучитьЗначение  V77Exp77 [Модуль отчёта] :4285
  ← ПолучитьРеквизитПКО  V77Exp77 [Модуль отчёта] :4250
  ← вне процедуры  V77Exp77 [Модуль отчёта] :4513
```

Политика глобального модуля настраивается: по умолчанию процедура без `Экспорт` считается
видимой только внутри глобального модуля (как в документации 7.7). Переменная
`ONE77_GLOBAL_ANY=1` возвращает прежнее «видно всё». На тестовой конфигурации ужесточение
ничего не изменило: 2 944 вызова глобальных процедур — все до экспортных, а 47
неэкспортных наружу не вызываются.

### Граф вызовов

```
onec77-md graph ПолучитьЗначение --direction down --depth 2
onec77-md graph ПолучитьЗначение --direction up --depth 1
```

```
Граф «ПолучитьЗначение»: кого вызывает, глубина 2, узлов 3, только символы конфигурации
ПолучитьЗначение
  → ВывестиСообщение  V77Exp77 [Модуль отчёта] :4327  (×8)
  → ПолучитьДатуV8  V77Exp77 [Модуль отчёта] :4352  (×2)
```

По умолчанию платформенные методы (`Сообщить`, `СоздатьОбъект`) отбрасываются — их не
рефакторят, а шума от них больше, чем пользы; `include_builtin=true` возвращает их обратно.
Одинаковые вызовы схлопываются в один узел со счётчиком, циклы помечаются, обход
ограничен глубиной (1–5) и лимитом узлов.

Чего пока нет: вызовов через строки (кнопки формы ссылаются на обработчик строкой
в `Dialog Stream` — `md_propose_rename` про них предупреждает, но сам их не правит)
и учёта двух одноимённых процедур внутри одного модуля.

### Предложи патч

Сервер не меняет базу. Он готовит unified diff и раскладывает файлы «до/после» в каталог:

```
onec77-md rename ПоискКонтрагента НайтиКонтрагента
onec77-md replace "СтарыйТекст" "НовыйТекст" --whole-word
```

```
Переименование «ПоискКонтрагента» → «НайтиКонтрагента»: модулей 1, замен 1
Файл: .../patch-ПоискКонтрагента-20261111-235500/changes.diff

--- a/Контрагенты__Модуль_формы_списка.txt
+++ b/Контрагенты__Модуль_формы_списка.txt
@@ -183,5 +183,5 @@
-Процедура ПоискКонтрагента()
+Процедура НайтиКонтрагента()

Внимание: на этот символ ссылаются обработчики форм (строки в Dialog Stream).
Их нужно поправить отдельно в Конфигураторе:
  - форма 1158, BUTTON: ПоискКонтрагента()
```

Замена идёт по маскированному тексту: комментарии и строковые литералы не трогаются,
поэтому `// ПоискКонтрагента` останется как был. Отдельно проверяются два риска —
совпадение с существующим символом и обработчики кнопок, которые на этот символ ссылаются
строкой. Каталог с патчем можно применить `git apply` или перенести правки руками.

## Индекс

Поиск по модулям идёт через SQLite-индекс: строки модулей складываются в таблицу `lines`,
поиск — `LIKE` по ней. На тестовой конфигурации это 201 367 строк, 38 МБ, построение 0,6 с, поиск 0,09 с
(перебор по Python — около 1,5 с).

```
onec77-md index            # построить/перестроить
```

Индекс лежит в `%LOCALAPPDATA%\onec77-md\cache` (переопределяется `ONE77_CACHE_DIR`) и
привязан к отпечатку базы: путь, размер, число объектов и модулей. Если индекс построить
нельзя, поиск молча откатывается на перебор — инструмент не падает.

## Экспорт и аудит

`md_export(fmt, kind, detail, out_path, inline)` пишет файл в `export/` (или в `out_path`) и
возвращает путь и размер. Форматы:

| Формат | Что внутри | Размер |
|---|---|---|
| `json` | полная модель: объекты, реквизиты, ТЧ, перечисления, формы, метаданные модулей | 1,0 МБ |
| `md` | справочник по видам: таблицы объектов; `detail=true` — ещё и реквизиты | 49 КБ |
| `mermaid` | `flowchart` связей: объекты по видам, стрелки по ссылочным реквизитам | 15 КБ |
| `sql` | DDL: `SC<id>`, `DH<id>`+`DT<id>`, `RG<id>` с реквизитами | 104 КБ |

`md_audit(rule, limit)` гоняет восемь проверок: `broken_refs`, `unused`, `duplicate_synonyms`,
`duplicate_declarations`, `missing_definitions`, `no_forms`, `no_transaction`, `empty`.
Результат на тестовой конфигурации:

```
Битые ссылки — 0
Неиспользуемые объекты — 211
Одинаковые синонимы — 2
Повторные объявления в модуле — 0
Объявлено, но не определено — 0
Объекты без форм и модулей — 0
Документы без модуля проведения — 3
Объекты без состава — 18
```

«Неиспользуемые» — эвристика: нет входящих ссылок и имя не встречается в текстах модулей;
журналы и отчёты могут попадать туда ложно, о чём отчёт честно предупреждает.

## Установка

```bash
# из исходников
pip install .

# или собрать wheel и поставить его
pip wheel . -w dist
pip install dist/onec77_md_mcp-0.3.0-py3-none-any.whl
```

Ставится консольная команда `onec77-md` и тот же код доступен как `python -m onec77_md`.
Зависимости (`mcp`, `olefile`, на Windows ещё `pywin32`) подтягиваются автоматически.

```bash
onec77-md --path /path/to/base info        # сводка
onec77-md objects --kind document --mask Акт   # список
onec77-md object --kind document АктНесоответствия  # карточка
onec77-md module ГлобальныйМодуль          # текст модуля
onec77-md export --fmt md --out ./out      # экспорт
onec77-md audit --rule unused              # проверки
onec77-md symbols ОбработкаПроведения      # где объявлено
onec77-md calls ПолучитьЗначение           # кто вызывает
onec77-md graph ПолучитьЗначение --depth 2 # граф вызовов
onec77-md rename СтароеИмя НовоеИмя         # предложить diff
onec77-md index --path /path/to/base       # SQLite-индекс для поиска
onec77-md serve                            # MCP-сервер (stdio)
```

Путь к базе берётся из `--path`, иначе из `ONE77_MD_PATH`.

## Запуск из исходников

Без установки, если зависимости лежат в `.deps`:

```powershell
$env:ONE77_MD_PATH = 'C:\Base\1Cv7.MD'
python C:\Projects\onec77-md-mcp\run_server.py
```

`ONE77_MD_PATH` задаёт базу по умолчанию; путь можно передавать в `md_config_info(path=...)`.

## Зависимости

Лежат локально в `.deps` (ставились `pip install --target`): `mcp`, `olefile`, `pywin32`.
`run_server.py` сам добавляет `.deps` и модули pywin32 в пути импорта (`src/onec77_md/bootstrap.py`),
поэтому глобальных установок не требуется. Другой каталог зависимостей задаётся `ONE77_DEPS_DIR`.

## Подключение в DSH

В профиль (`~/.dsh/profiles/desktop/cordis.patch.yml`) добавляется блок `- insert:` —
top-level запись `- id: ...` в патче работает только как override существующего плагина,
новый сервер она не добавляет:

```yaml
- insert:
    - id: mcp-onec77-md
      name: '@deepseek-ai/dsh-mcp-client'
      config:
        serverName: onec77md
        transport: stdio
        command: 'C:\Tools\python.exe'
        args:
          - 'C:\Projects\onec77-md-mcp\run_server.py'
        cwd: 'C:\Projects\onec77-md-mcp'
        env:
          ONE77_MD_PATH: 'C:\Base\1Cv7.MD'
        toolCallTimeoutMs: 120000
```

Инструменты появляются как `mcp__onec77md__md_*`. Проверить, что сервер поднялся, можно по
файлу `.cache/server.log` — он пишется при каждом старте процесса.

## Как это работает

1. `1Cv7.MD` — OLE2-контейнер. Поток `Metadata/Main MetaData Stream` — текст CP1251
   с деревом секций `{a,b,{c,d}}`.
2. `parsing/sections.py` разбирает дерево в вложенные списки (без `eval`).
3. `model/mapping.py` раскладывает секции (`SbCnts`, `Documents`, `Registers`, `EnumList`, …)
   в `MdObject`/`Field`, разрешая ссылки по id таблиц (`B`→справочник, `O`→документ, `E`→перечисление).
4. `server.py` отдаёт модель через MCP (stdio).

Загрузка тестовой конфигурации (671 объект, 16 МБ) занимает ~0.1 с; кэш держится по mtime и размеру файла.

Тесты парсера синтетические; тесты модели, форм и индекса проверяются на реальной базе
и пропускаются, если `1Cv7.MD` недоступен (путь задан в `tests/*.py`).

## Ограничения текущей версии

- Разбор языка строчный, без полного AST: разрешение вызовов эвристическое (локальное /
  глобальное объявление / единственное экспортное / неоднозначно). Обработчики кнопок
  индексируются и видны в поиске, но патч их не меняет — строки лежат в `Dialog Stream`.
- Страницы формы `Page.1`/`Page.2` (Moxcel-таблицы) не разбираются — только `Dialog Stream`
  с элементами. Вложенность групп в разметке не восстанавливается: элементы идут плоским списком.
- В текстовой выгрузке нет модулей — только описание метаданных.
- Экспорт `sql` — приблизительный: имена таблиц и колонок по конвенции платформы, сверяйте с базой.
